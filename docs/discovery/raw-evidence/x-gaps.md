# Section L — Missing Enterprise Capabilities (Cross-System Gap Analysis)

**Scope:** Capabilities ABSENT from BOTH systems that an enterprise-grade CRM + customer master-data platform for a multi-depot FMCG/distribution company (NMWC SAOG) would normally require. Read-only discovery; no project file modified.

- **OLD** = ICO Customer Portal (`C:\Users\abdulr\Desktop\ICO\customer-portal`) — a **workflow/approval tracker**, NOT the system of record (portal never writes `CustomerMaster` from the workflow — old-functional §4 CRITICAL FINDING; old-rules §L).
- **NEW** = NMWC-CRM (`C:\Users\abdulr\Desktop\NMWC-CRM`) — an **edit-only master-data enrichment** tool over ~3,000 pre-loaded records; IS the system of record for enrichment (apply-on-approve) but has **no ERP integration** (new-arch §9, grep-negative).

**Method:** synthesized from all 13 per-system discovery findings + targeted spot-checks (i18n/RTL, VAT/tax/credit fields, PWA/offline, charts) run this pass.

**Classification legend:** **[E]** Essential-for-first-release · **[I]** Important-but-later · **[O]** Optional-enhancement · **[N]** Not-recommended-unless-confirmed.
**Confidence:** [Confirmed]=read in code/discovery evidence · [Highly likely] · [Possible] · [Unknown].

**Critical framing:** NEW is a *master-data cleanup* tool by design (new-docs §1: new-customer creation and credit/AR are explicitly out of scope; ERP "Temix"/"RoutePro" own transactions). Many "enterprise CRM" features (credit risk, AR, pricing, orders) legitimately belong in the ERP, NOT here — inflating the CRM with them would be wrong. Gaps below are judged against what a **customer master-data governance** platform for NMWC actually needs.

## L.2 The five gaps that most matter for NMWC (ranked)

1. **[E] ERP system-of-record strategy & sync (#22).** Neither system closes the loop to Temix/RoutePro automatically. NEW produces clean Excel that a human re-keys — error-prone and unauditable end-to-end. Before consolidation, NMWC must decide: is NEW the SoR for customer master attributes (GPS/contact/channel/photos) with Temix as SoR for financial/transactional data, and how do the two reconcile? Even a documented batch-Excel contract with conflict rules is a decision, not a feature — but it is Essential. [Confirmed: OLD old-functional §4; NEW new-arch §9.]
2. **[E] Coherent, operable customer lifecycle (#1, #19).** SUSPENDED dead-ends, un-closable customers, and import-only creation mean the master cannot represent real-world states. [Confirmed: new-functional §3b, gaps 3-4.]
3. **[I, adoption-critical] Arabic/i18n/RTL (#31)** — English-only UI for Arabic-speaking field staff is the top *adoption* risk once past a hand-picked pilot. [Confirmed spot-check.]
4. **[I] Notifications + SLA + escalation + delegation (#8, #25-27)** as a bundle — the approval loop currently relies on polling and stalls when an approver is absent. All effectively absent in both (OLD's are dead code). [Confirmed.]
5. **[I] First-class version history + data-quality monitoring (#12, #15)** — governance essentials for a master-data platform; NEW deferred the relational field-history table (B-22) and has only completeness scoring. [Confirmed: new-docs §5; new-techdebt TD-6.]

## L.3 What NOT to build (avoid feature inflation)
- **Credit/AR/credit-risk/cash-credit approval (#5, #6)** — ERP (Temix) territory. **[N]** unless NMWC explicitly reassigns credit onboarding to the CRM.
- **Full WCAG accessibility, native mobile app, territory-realignment analytics, in-app training, support impersonation console (#21, #29, #32, #35, #36)** — **[O]**; real but premature for a ~3,000-record Muscat pilot. Revisit at multi-depot scale.
